You are a senior full-stack engineer.

Implement FULL CCAvenue payment gateway integration in the existing “Bachan Gas Service” Next.js (App Router) + Tailwind + Next API Routes + SQLite + Prisma system.

GOAL:
- Customers can pay via CCAvenue for orders/receipts.
- System automatically adds a configurable “CCAvenue Convenience Fee” (default 0.25%) to the payable amount BEFORE redirecting to CCAvenue.
- Admin can enable/disable CCAvenue and enable/disable the convenience fee using toggle switches in Admin Settings, and can change the fee percentage.

Must run on Replit one-click. Use env vars for secrets.

=====================================================
A) CCAvenue PAYMENT FLOW (MUST)
=====================================================
Implement the standard CCAvenue hosted checkout redirect flow:

1) Customer chooses payment method = CCAvenue on Payment screen.
2) Backend creates a PaymentIntent/Transaction record with:
   - baseAmount (order amount)
   - convenienceFeeAmount (if enabled)
   - totalPayableAmount = baseAmount + convenienceFeeAmount
3) Backend generates encrypted request payload (per CCAvenue requirements) and returns a redirect URL or auto-post form.
4) Frontend redirects/posts to CCAvenue payment page.
5) CCAvenue redirects back to:
   - success URL (/payment/ccavenue/success)
   - failure URL (/payment/ccavenue/failure)
6) Backend verifies and decrypts the CCAvenue response.
7) Mark transaction as PAID or FAILED and update order/receipt status.
8) On success:
   - generate receipt PDF + QR
   - send receipt on WhatsApp automatically
   - show “Payment Successful” page with receipt link

=====================================================
B) CONVENIENCE FEE (DEFAULT 0.25%) (MUST)
=====================================================
Requirement:
- When payment method is CCAvenue, add a convenience fee of 0.25% (default) on base amount.

Example:
- Base amount = 2525
- Fee rate = 0.25% = 0.0025
- convenienceFeeAmount = 2525 * 0.0025 = 6.3125
- Round policy:
  - Round to 2 decimals for currency, then final payable rounded to 2 decimals
  - Or round up to nearest rupee (Admin configurable) — pick one and document it.
- totalPayableAmount = 2525 + 6.31 = 2531.31 (example)

IMPORTANT UI:
- Before redirecting to CCAvenue, show breakdown:
  - Amount: ₹2525.00
  - CCAvenue Convenience Fee (0.25%): ₹6.31
  - Total Payable: ₹2531.31

E) API ROUTES (MUST)
=====================================================
Public/Auth (Customer/Delivery):
- GET /api/settings/payments
  - returns ccavenueEnabled, feeEnabled, feePercent, roundingMode

CCAvenue:
- POST /api/payments/ccavenue/initiate
  Input:
  - receiptId (or orderId/tripStopId)
  Output:
  - redirectUrl OR auto-post form data required by CCAvenue
  Behavior:
  - verify ccavenueEnabled
  - compute convenience fee if enabled
  - create PaymentTransaction(status=INITIATED)
  - generate encrypted request and return

- POST /api/payments/ccavenue/callback
  - called by CCAvenue redirect response (working with success/failure)
  - decrypt response
  - verify amount matches PaymentTransaction.totalAmount
  - mark PAID/FAILED
  - on PAID: generate receipt, WhatsApp send

Pages:
- /payment/ccavenue/success (shows success UI, fetches receipt)
- /payment/ccavenue/failure (shows failure UI, retry button)

Admin:
- GET /api/admin/settings/payments
- PATCH /api/admin/settings/payments (toggle + percent + rounding)
- GET /api/admin/transactions (filter by gateway/status/date)

All routes RBAC protected where needed.
